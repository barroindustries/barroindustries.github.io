# PUBLIC-WEBSITE-SPEC — barroindustries.com as a public business website ("same URL, smart switch")

_Written 2026-10-21 (Fable, architecture tier). Implementer: Sonnet, max effort. Follow exactly; escalate ambiguities, do not improvise._

## 0. Summary

`/` (repo-root `index.html`, GitHub Pages) becomes a **public, light, catalogue-style website** for Barro Industries OPC / Barro Kitchens™. A **"Login" button at the top right** reveals the EXISTING login screen (unchanged portal flow: Admin / Employee / Partner). Signed-in users and the installed PWA boot straight into the app exactly as today. No URL moves; no Firestore/Storage rules change; nothing in the auth, nav, or router semantics changes beyond the three view-switch hooks listed in §5.3.

The mechanism is a single `data-view` attribute on `<html>` with four values — `boot | site | login | app` — set **synchronously before first paint** by a tiny inline `<head>` script (localStorage hint + standalone detection + hash), then corrected by `showApp()` / `showLogin()` / `showSite()` once Firebase auth resolves. CSS keyed on that attribute decides which of `#site`, `#splash-screen`, `#login-screen`, `#app-shell` is visible. The website markup is **static HTML inside index.html** (crawlable, no-JS-safe), with the product catalogue **generated at build time** from the private master JSON by a script that strips every price field, guarded by a new ci-invariants check and a unit test.

## 4. Architecture decision

### 4.1 Static markup inside index.html (chosen) vs separate partial

**Chosen: static HTML in `index.html`.** Reasons: (a) crawlers and no-JS visitors get the full page — a fetched partial would index as an empty shell; (b) `'/'` and `/index.html` are already in PRECACHE and in `PRECACHE_ALWAYS_FRESH`, so the site ships with the normal deploy with no new cache entries; (c) the pre-commit hook rewrites only the literal `v14.0.NNN · Barro Industries` string and the `css/(tokens|styles).css?v=` markers — the site markup must simply **never contain the pattern `vN.N.N · Barro Industries`** (footer copy in §6.8 avoids it); (d) ci-invariants CHECK 2 greps `(src|href)="js/…|css/…"` in index.html — every new local js/css reference must be in PRECACHE (§5.1 covers this).

Cost: index.html grows from 36 KB (12 KB gz) to roughly 80–90 KB (≈20 KB gz) with the full catalogue. Acceptable: it is network-first with a 3 s ceiling and always-fresh in the SW.

### 4.2 Pre-paint view decision (no-flash routing)

Today: `#splash-screen` (fixed, `z-index: var(--z-splash)`) paints over `#login-screen` (visible by default) and `#app-shell` (`.hidden`). `auth.onAuthStateChanged` (`js/app.js` ≈L140) then calls `showApp()` or `showLogin()`, each of which calls `hideSplash()` (400 ms floor). Theme is applied pre-paint by the inline script at `index.html` L27–38.

New: a second inline script (immediately after the theme script, still before the stylesheets) computes the initial `data-view`:

```
standalone := matchMedia('(display-mode: standalone)').matches
           || matchMedia('(display-mode: fullscreen)').matches
           || matchMedia('(display-mode: minimal-ui)').matches
           || matchMedia('(display-mode: window-controls-overlay)').matches
           || navigator.standalone === true
hint       := localStorage.getItem('bi-auth-hint') === '1'
hash       := location.hash
appHash    := hash starts with '#/'          (manifest shortcuts, notification deep links, bookmarks)
loginHash  := hash === '#login'

if standalone            → data-standalone="1", data-view="boot"
else if hint or appHash  → data-view="boot"
else if loginHash        → data-view="login", window._wantLogin = true
else                     → data-view="site"
```

Everything in `try/catch`; on any throw → `data-view="boot"` (today's behaviour). `boot` = splash over login, exactly today's first frame.

| Scenario | First paint | After auth resolves | Flash? |
|---|---|---|---|
| Signed-out visitor, browser | site | `showSignedOut()` → `showSite()` (no-op visually; also `hideSplash()`) | none |
| Signed-in user reload, browser (hint='1') | splash | `showApp()` | none (as today) |
| Installed PWA, any auth state | splash | app, or login (never site) | none |
| Hint stale: session ended elsewhere / expired / SESSION-persistence (unticked "Keep me signed in") | splash | null → `showSignedOut()` → site; hint cleared | splash for one auth round-trip, then site (acceptable; same as today's splash→login) |
| Hint missing but IndexedDB auth still valid (localStorage cleared separately — rare) | site | `showApp()` | website visible for one auth round-trip, then app. Mitigation: `showApp()` re-sets the hint every time, so this self-heals on the next load |
| Force-logout / auto-logout (browser) | — | null → site (toast "Signed out due to inactivity" still shows; toasts are z≥9000) | none |
| Force-logout / auto-logout (installed) | — | null → login | none |
| Removed-user gate | — | overlay (`#removed-user-screen`, z-splash) over whatever is shown; hint cleared | none |
| Wrong-portal gate | login | stays on login with the error (`_wantLogin` stays true until `showApp()`) | none |
| Visitor clicks **Login** before auth resolved | site → login (+ splash if still pending) | login or app | none |

**Hint lifecycle** (`localStorage['bi-auth-hint']`): SET to `'1'` in `showApp()` (the only place a user is confirmed signed in and bootstrapped). REMOVED in `showSignedOut()` (the null branch, which every sign-out path funnels through: explicit, inactivity, force-logout, removed-user, wrong-portal) and in `showRemovedUserScreen()`. Never set anywhere else. All reads/writes in `try/catch`.

### 4.3 Theme independence

Staff devices may have `html.theme-dark` / `theme-astral` persisted. The website must be white regardless: `css/site.css` defines its own `--site-*` tokens scoped under `#site` and never reads `--bg/--text/--primary`. `#site` sets `background:#fff; color:#111; min-height:100dvh` so `body{background:var(--bg)}` is fully covered. `<meta name="theme-color">` is already `#FFFFFF`.

### 4.4 Performance

- All scripts are already `defer`; HTML + CSS paint first. The two stylesheets are render-blocking: `tokens.css` (4.5 KB gz) + `styles.css` (**129 KB gz**) + the Inter `@import`. Visitors pay that once (then SW/HTTP cache). **Do not** make `styles.css` async — the splash/login first frame depends on it. Accept and record; follow-up option (not this build): split a critical subset.
- `css/site.css` (target ≤ 12 KB raw) loads **after** `styles.css` (so its `#site` rules win on specificity ties) and is the only new stylesheet.
- `js/site.js` (target ≤ 6 KB raw, zero dependencies, no `window.*` reads at parse time) is placed as the **first** `<script defer>` — before the Firebase SDK — so catalogue filtering/lightbox/Login work as soon as parsing ends, without waiting for ~1 MB of SDK + app code to execute. This does not alter the documented load order of the existing chain (it only adds one independent file in front of it); document that in the index.html comment.
- Firebase SDK, Chart.js, Lucide: unchanged (Chart.js is already lazy). The site uses **inline SVG** icons only — never `data-lucide` — so it never waits on Lucide.
- Service worker registration (`js/app.js` ≈L5620): unchanged. Visitors will precache the app shell in the background (≈1.6 MB); it does not affect paint. Noted as an optional later optimisation ("register SW only when view ≠ site"), NOT part of this build.
- Project photos: `loading="lazy" decoding="async"`, explicit `width`/`height` to avoid layout shift.

### 7.2 `scripts/build-catalogue.js` (Node ≥ 18, no dependencies)
- Usage: `node scripts/build-catalogue.js [path/to/products-database.json]`. Default input: `./products-database.json` if present, else `~/Desktop/barro-private/products-database.json`. Fails loudly if neither exists. Strips `//` and `/* */` comments before `JSON.parse` (the master carries JS-style comments — see `js/app.js` ≈L2510 which does the same).
- Exports `publicProduct(p)` and `renderCatalogue(db)` (so the test can import them) and only runs `main()` when executed directly.
- **Allowlist (the only fields that may reach the output):** `id`, `name`, `category`, `unit`, `defaultDimensions.{W,D,H}`, `material.{grade,topGauge,bodyGauge,frame,finish,…}` (string values only), `notes`, `specs[].label` and `specs[].options` (NEVER `priceAdder`, NEVER `default`'s price). Everything else — `basePrice`, `formula`, `formulaType`, `laborHours`, `leadTime` (O1), `laborRoles`, `constants`, `_meta` — is dropped by construction (build the output object field-by-field; never spread).
- **Money scan:** throw if any emitted string matches `/₱|PHP ?\d|\b\d{1,3}(,\d{3})+\b|price|cost|markup/i`. Current notes such as "Base install cost; varies per project size" (MS-005/006) **will trip this** — the script must replace that sentence with "Scope varies per project" via an explicit `NOTE_OVERRIDES` map keyed by product id, and the run must report every override applied. Do not loosen the regex.
- HTML-escape every string (`&<>"'`) with a local `esc()`; the output is static so `escHtml()` from modules.js is not available at build time.
- Output: replaces everything between the two marker comments in index.html (`<!-- CATALOGUE:START generated by scripts/build-catalogue.js — DO NOT HAND-EDIT -->` … `<!-- CATALOGUE:END -->`), preserving the rest byte-for-byte. Fails if markers are missing or duplicated. Prints counts per category and the total (must be 165 / 9 for the current master).
- Products are sorted by category order in the master, then by `id`.
